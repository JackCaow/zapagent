# Glob 接入 ripgrep 与检索覆盖范围

## 改动

`glob_files` 使用 `rg --files --null` 流式枚举，保持相对根目录的现有 glob 匹配语义。
匹配在枚举后进行，不用 positive `--glob` 强制重新包含已经忽略的目录；因此 `*.ts`
仍只匹配根目录，`**/*.ts` 匹配任意层级。换行文件名使用 NUL 分帧并在显示时转义。

Glob 与 Search 共用 `builtin-tools/ripgrep.ts`：延迟定位内置/系统 rg，通过执行 broker
启动进程，消费 stdout/stderr，限制输出缓冲、处理超时、取消与退出状态。两个工具均包含
隐藏文件、应用非 Git 项目的 ignore 文件，排除 `.git`/`node_modules`，并禁用隐式 rg config。
Search 保留原有 native rg 内容正则和显式 `glob` 参数语义；Glob 保留原有根目录相对匹配器。
这次统一的是后端发现、进程执行和覆盖状态，不宣称 JS 与 rg 的全部 glob/ignore/正则语义等价。

## 容量与覆盖契约

- 移除 Glob 默认 10,000 遍历条目上限。默认返回最多 500 个匹配路径；时间和输出容量仍有界。
- `limits.maxFiles` 限制返回路径数，与 Search 的结果预算一致。SDK 显式传入
  `maxVisitedEntries` 时仍执行该遍历预算；native 统计枚举的文件，JS 统计目录条目。
- 原有默认目录深度 64 和更严格的 host 深度限制保留；Glob 输出明确写出检索范围。
  `complete` 表示当前声明的根目录/深度/忽略规则范围内完成，不代表扫描所有磁盘文件。
- 多读一个匹配以区分“恰好达到返回数”和“结果已截断”。截断保留已找到的路径，并在正文
  及 `meta.search` 标注原因。Search 使用 rg JSON 事件按全局匹配记录计数（多行匹配按块），
  上下文不占匹配数量，输出字节另行限制。原来按单文件 `--max-count` 限制却不标记缺失的
  行为被移除。只提交已接受匹配的前后上下文，超额匹配的独立前文不进入输出。
- 输出预留诊断空间；超长单条记录、输出上限、遍历上限、stderr 警告都会暴露覆盖限制。
  只有正常退出且未截断的检索可报告无匹配；不完整检索不能证明未检查内容中不存在目标。
- 权限检查先于启动进程；Glob 声明与 Search 相同的只读 `search` 进程效果，进入原执行 broker。
  不跟随目录符号链接，不借本次改动新增路径授权。
- rg 不存在或启动 ENOENT 才可使用 JS 回退。权限/策略拒绝、非正常退出、无效正则、超时和
  取消均保留失败，不静默切换实现。stderr 同时消费，避免错误管道堵塞。
- JS Glob 改用流式 `opendir`，没有默认一万条目上限；保留结果并报告深度、容量和不可读目录。
  现有 JS ignore 仅支持根 `.gitignore` 的子集，因此回退输出始终披露语义限制，不宣称完整覆盖。

根相对 glob/花括号、中文与换行文件名、目录符号链接、精确结果边界、多一个结果截断、

## 独立审查与修复

两个独立 agent 分别审查检索语义、权限与覆盖契约，以及进程生命周期与记录完整性。
初审发现 3 项 P2，修复后的复审又发现 JSON 模式引入的二进制诊断缺口，均已修复：

1. **上下文挤掉命中**：原行数预算使 `maxResults: 1` 只返回匹配前一行。改用 JSON
   `match` 事件计数，保留命中和上下文；解析不依赖文件名中的冒号、连字符或换行。
2. **半条 NUL 记录变成路径**：仅接受 NUL 闭合的文件路径，异常退出不消费尾部碎片。
   正常文本流仍可接受没有末尾换行的最后一行。
3. **结果上限掩盖错误**：保留同时发生的真实错误退出码；主动终止进程产生的信号退出
   仍允许返回部分成功。正文合并错误、截断和 stderr 诊断。
4. **二进制文件误报完整**：消费 `end.binary_offset`，标记不完整并提示文本结果及行号限制；
   覆盖目录中晚出现 NUL 和显式单文件两种情况。

额外按渲染后的字节逐行计费，避免长路径在多行匹配中反复展开后才检查容量。
两位审查 agent 在最终复核中均未发现其他已确认的可行动问题。

审查后验证：
