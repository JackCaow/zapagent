[竞品与现场证据](64-permission-mode-research.md) · [实施与验收](66-permission-mode-tasks.md) · [默认 Auto 工作流程](63-auto-workflow-requirements.md)

## 用户目标

用户在项目里直接交代任务，常规开发与查看产物能完成。需要扩大实际范围时，Zap 显示具体操作和目标。Zap、Codex、Claude Code 对同一模式兑现同一用户承诺。复用现有模式入口、状态栏及 /permissions 的工作区、规则和近期拦截。兼容现有 headless、SDK 和 VM 接口，日常交互沿用自然语言发起分析与实施。

## R1 · 三档的用户承诺

| 操作 | Auto（默认） | Manual | Bypass |
| --- | --- | --- | --- |
| 现有范围内读文件、搜索、查看结果 | 直接执行 | 直接执行 | 直接执行 |
| 编辑工作区、运行 Shell | 在执行端能强制遵守已获范围时直接执行。边界不明时确认具体调用 | 编辑和 Shell 逐次确认 | 实际约束覆盖已有授权时直接执行 |
| 用户要求打开项目产物 | 通用本地预览直接展示。需要额外权限时说明具体动作 | 只读预览直接展示。启动未授权外部程序时确认 | 在已授权范围内直接展示或执行 |
| 发布、推送或写外部服务 | 已有明确外发授权时按规则执行，否则询问具体目的地与操作 | 逐次确认 | 已授权的目标直接执行，未授权目标拦截 |
| 显式拒绝、硬限制、撤销 | 拦截 | 拦截 | 拦截 |
| 命中显式 Ask 规则 | 显示审批 | 显示审批 | 拦截并指出该规则。用户可换模式或调整规则 |

Bypass 开启时显示本次会话可执行的范围。选择模式本身不创建额外目录或网络授权。Shift+Tab 在 Auto 与 Manual 间切换，Bypass 从 /mode 显式开启。项目授权仍在 /permissions 管理。新会话和升级后的旧配置从 Auto 启动，模式菜单提供 Bypass 的范围说明。显式 Ask 规则在 Bypass 中拦截，避免用户自己写下的限制被静默覆盖。

## R2 · 授权由实际边界兑现

- 复用现有项目身份、一次/会话/项目规则和审批队列。仓库可收紧约束。项目授予从宿主用户数据验证，项目内容和模型文本不能自行提权。现有精确命令规则保持原范围。
- 执行前核对实际目录、目标、运行身份和授权状态。宿主边界与显式拒绝优先，其次按 Ask、有效授权和模式裁决。
- 复用现有 broker 或原生运行时能证明的约束。对自由 Shell，只有能限制文件和实际出站访问时，才可承诺自动执行保持在指定范围内。已有代理仅能约束域名时，允许该域的 Shell 出口须按可能写入处理。外发有可验证工具入口时复用其目标和操作事实。
- 本地预览是通用产物交付能力。检查真实路径、当前项目归属及查看器访问范围，同一个入口处理 HTML、SVG 和其他产物。离线预览展示文档、图片或文本，主动脚本和远程资源由原文件承载。只有浏览器启动成功时才报告已打开。环境不支持时交付路径和具体原因。

## R3 · 执行适配

Zap 自有工具复用 effects、执行 broker 和审批队列。Codex 沿用 ACP，Claude Code 沿用 stdio 请求。映射前验证运行时能强制执行的范围和可转发的审批。无法实现某个模式或目标时，显示实际生效范围及原因，并约束相关动作。

Codex Manual 的现有故障须在真实链路定位并修复。等待状态区分需要用户动作、原生执行限制和原生审批通道故障。Codex 的原生 PermissionRequest hook 可能先处理请求。集成须保留已有的管理策略，并明确显示审批由谁处理。断线、取消或授权失效时退出等待。在三条已声明受支持链路完成真实批准、拒绝和结果核对之前，不发布统一模式能力。

## R4 · 生命周期与结果

- 子 agent 权限是父任务权限与子任务范围的交集。后台续跑绑定原任务来源和有效授权。恢复会话只引用仍有效的项目授权。
- 同项目跨窗口撤销立即影响新的裁决，取消受影响的等待和执行。重新授权后，旧子 agent、后台任务、待审批回调和旧续跑仍失效。对无法证实已退出的原生进程，显示真实状态并拦截后续工具动作。
- 以文件、进程或外部接收端的实际结果交付。撤销不抹去已经发生的写入。普通回合直接收尾；错误仍可见，拒绝和失败不会触发通用重放。

**验收**以安装产物、专用 tmux、本机回环接收端及实际文件变更为准。指定日常流程在 Auto 出现 0 次审批。发布拒绝后写入 0 次、批准后恰好 1 次；Bypass 已授权范围内 0 次再次确认，范围外写入为 0；撤销后旧运行写入为 0。兼容验证、复审、CI、发布产物和 npm 校验全部通过后交付线上验收。
