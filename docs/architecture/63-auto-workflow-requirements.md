# Zap 默认 Auto 工作流程需求

记录日期：2026-11-27

状态：已实现，已通过 macOS 本地验证

## 从一次普通开发对话说起

用户在 Zap v1.14.33 里使用 Claude Code，说「我要做个网页科普磁力」。Claude 列出五个问题，随后给出单文件网页方案并承诺确认后实施。用户回复「确认」，再说「打开我看看」，页面始终没有创建。Claude 建议使用 Shift+Tab 或 `/plan`。Zap 不识别 `/plan`，状态栏则提示 `Analyze · /work to edit`。

这是 Zap 的默认流程问题。一个未取得项目授权的交互回合会被转换为只读计划回合。Claude 收到 plan 模式和只读工具列表，Codex 走 read-only 工作区。现有「仅本次任务」授权在单回合结束时释放，下一条普通追问可能再次落入只读。模型可以输出计划，但一条普通的「确认」不会改变宿主的执行权限，也就无法兑现「确认后开始」的承诺。

现有代码入口：[任务授权](../../src/workspace-access.ts) · [应用回合分发](../../src/App.tsx) · [Claude 启动](../../src/agent/claude-code.ts) · [Codex 会话配置](../../src/agent/official-agents.ts)

## 产品决定

- **Auto 是交互会话的默认体验。** 用户打开项目，描述想做的事，agent 就能推进。项目内的常规读取、编辑和验证走通后，再处理少见的权限边界。
- **从 `/mode` 去掉 Plan，加入 Auto，移除 `/work`。** 普通用户凭自然语言完成工作。`/mode` 用于调整工作方式，显式项目授权在 `/permissions` 管理。
- **模型负责安排工作。** 简单任务直接做，复杂任务自行拆解。只有缺少会实质影响结果的信息时才提问。低成本、可逆的选择可以先按合理默认执行，并说明假设。
- **尊重用户明确提出的范围。** 「先出方案，别改文件」时只分析。「开始做」或明确确认实施后，接上原任务，直到交付和验证。普通对话里的「确认」按上下文理解，敏感授权由 Zap 的可信交互授予。
- **回复要像同事说话。** 说明做到了哪一步、结果在哪、还差什么。如果需要用户选择，讲清具体动作和影响。避免交一份问卷、抛出内部模式名，或让用户猜该输哪个命令。

## 项目操作与适配要求

| 场景 | 预期行为 |
| --- | --- |
| 在项目中请求实现、修改或修复 | Auto 允许在当前工作区内读写和运行常规项目检查，例如构建与测试。正常步骤不要求先输入命令、批准计划或逐个批准文件操作。 |
| 继续修改、修测试、看结果 | 保留已完成的工作和对话上下文。新消息可以继续操作当前项目。用户要求预览时，先确保产物存在，再通过可用的预览入口展示。 |
| 需要额外权限 | Zap 在具体操作发生时说明要做什么、涉及哪个位置，并提供适用选项。显式拒绝、越界写入、外部发布和危险命令继续按现有规则处理。 |
| 用户希望记住项目授权 | 由 Zap 按实际项目身份和授权范围保存用户选择。授权可撤销，不随目录替换、会话文本或模型指令转移。一次授权与长期选择的差别用自然语言说明。 |
| Claude Code 和 Codex | Zap 对两者提供相同的产品行为。适配层使用已安装的官方运行时，协商可用的工作区权限、转发审批并保持对话。让模型收到 Zap 当前可用的行动方式，避免指导用户使用原生 CLI 的快捷键。 |
| 子 agent 与后台续跑 | 子 agent 在分配的目录内继承父任务所需的权限，范围不得因委派扩大。后台续跑只有在宿主能核对原任务、项目和授权仍然有效时，才可继续写入。 |
| 重启、更新或切换 agent | 恢复任务时复用仍有效的项目授权。过去的聊天内容不产生新权限。原生会话无法续接时，应让用户知道当前上下文能恢复到哪里。 |

Auto 是 Zap 的交互默认方式。底层只读能力可继续服务于明确的只读请求、隔离角色和兼容入口。既有 headless、SDK 调用及其权限参数是否迁移，单独评估。

Auto 是宿主策略。每轮由 `WorkspaceAccess` 根据消息来源和项目身份确定当轮权限，工具审批层继续判断具体动作。Claude 和 Codex 适配同一个裁决。子 agent 继承父运行身份和分配的目录，无法自行扩大授权。后台任务的续跑记录在进程内与来源任务绑定，消费后失效。重启后只有独立保存的项目授权可恢复。

## 交付顺序

1. **先疏通主流程。** 落地 Auto 默认、更新 `/mode` 和状态栏，让空项目里的第一条开发请求及后续修改能完成。接通 Claude、Codex 的实际写入和测试链路，保留可操作的边界提示。
2. **补齐生命周期。** 核对一次授权的实际范围、撤销后的在途任务、子 agent 继承、后台续跑和恢复。后台事件能证明原任务身份时继续做事，证据不足时沿用受限行为。
3. **按用户任务验收。** 用真实 TUI 验证普通对话和异常分支，录下操作及实际结果。

首批需求来自「先松绑，流程要跑通」。Auto 的授权随前台任务产生，并由当前工作区与运行身份限定。同一会话中的后续人类消息各自发起任务。后台续跑必须带有宿主记录的任务来源。项目级授权由独立的显式设置管理。

## 验收用例

| 用例 | 通过标准 |
| --- | --- |
| 从空目录做网页 | 在全新临时目录启动 Zap，直接说「做一个中文磁力科普网页」。实际生成可打开的单文件网页并验证，过程无需 `/mode`、`/work` 或额外的计划确认。 |
| 连续跟进 | 同一对话再说「改一下配色，再检查手机宽度」「打开我看看」。看到原文件被修改、验证结果与可打开的预览。 |
| 用户主动限制 | 先说「给个方案，先别写文件」，检查目录无新增业务文件。再说「就按这个做」，实际生成文件并核对结果。 |
| 审批与撤销 | 请求当前项目以外的写入时，Zap 清楚解释请求。拒绝后目标不变。撤销长期授权后，旧授权不能继续放行。 |
| 继承与恢复 | 子 agent 能完成分配范围内的工作，越出范围时正确受限。测试任务完成后的合法续跑可继续原任务，已经撤销或过期的授权不能续用。 |

网页是复现和验收样例。真实验证要用隔离目录和独立 Zap 数据，在 tmux 中分别跑 Claude Code 和 Codex，保留终端录制与产物或测试结果。界面、实际文件变化和测试输出必须能互相印证。

本地验证中，两条原生会话均创建和修改了网页，运行语法检查，并给出可打开的路径。Chrome 在 390px 视口分别验证了布局和磁极切换。前台连续编辑、已绑定的后台续跑、撤销项目授权，以及 `/mode` 入口由 tmux 回归覆盖。

## 移除内置清单

Zap 自带的清单工具、清单界面和规划门槛一并移除。模型自行组织工作，后台续跑由任务完成事件触发，Goal 通过自己的状态和独立验收推进。旧会话恢复时跳过历史清单调用。
