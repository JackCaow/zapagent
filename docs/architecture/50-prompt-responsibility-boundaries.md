# 提示词职责分层与对照验证

状态：已实现显式选择的 profile，生产默认仍为 `standard`；新 profile 的 Bench 收益尚未验证。下文历史探索基线为 `9c561fe4`。

## 独立解题证据前提

本文历史表格记录的是各轮官方原始评分，不代表已完成独立解题审查。后续对
`08c2e779` 的轨迹审计发现：Pro 的 GPT2 trial 获取了公开参考解答脚本，Flash 的
GPT2 trial 访问了 benchmark 题目页面。前者不能用于独立能力归因，后者存在来源
暴露、仍需进一步审查；这些发现不能直接外推为其他历史 trial 也使用了参考答案。
原始分数和失败记录保留，来源资格单独记录，不能因官方评分正常而省略审查。

后续模型或 profile 对照必须对所有题目施加相同的通用独立解题要求，允许使用题目
提供的文件和普通技术资料，禁止获取参考解答、隐藏测试或其他 Agent 的题目解答轨迹。
新增这项要求会改变模型输入，因此受此约束的新基线不能当作旧轮次的纯运行时消融。
题目主动提供的测试和代价模型属于合法输入；不能仅因文件含有 benchmark 标记就将其
判为答案污染，也不能将公开参考解答误当作普通技术文档。

适配器的来源筛查只是审查入口。阴性结果 `not_detected_review_required` 不等于独立性
通过；还需保留并审查完整工具参数、结果、生成代码的文件/网络操作，以及工具调用与
结果配对和运行终态。记录审查覆盖范围、缺失证据与局限，不声称网络隔离或模型训练数据
无污染。官方正确性评分与来源审查结论分开呈现。只有来源证据满足比较要求，才用评分
差异决定是否推广 profile；不得拼接不同模型、版本或轮次的成功题来宣称整体通过。

还须独立核实 verifier 是否实际进入测试。依赖下载失败可能使 setup 脚本写出官方
0 分，而 Harbor 没有记录执行异常；这不能证明模型答案错误。保留原分数，另外记录
setup 失败、测试已执行或证据不足，并将审查绑定到 trial、result 与 verifier 日志的
hash。未知或过期审查不参与能力归因。已进入测试后，被测程序超过测试时限仍是测试
失败，不能因为含有 timeout 就归为环境故障；本地自测通过也不能替代官方验收。

## 为什么现在检查提示词

该版本在原定五题样本中通过 4/5，五题均自然结束，未发生环境异常。
唯一失败题交付的实现输出错误，没有触发上下文压缩。其运行约 75% 的时间位于
模型请求区间，收尾约 48 ms；模型请求时间包含网络和服务等待，不能等同于推理耗时。
这些证据支持检查决策所接收的信息，但不能证明提示词导致失败或模型已达到能力上限。

真实 Linux Bench 的持久化诊断显示固定前缀为 23,184 字符，工具 schema 为 27 个。
本机模拟 provider 的 CLI 样例为 40,652 字符，其中技能目录占 17,964 字符。
本机技能发现与容器不同，不能把本机长度当作 Bench 的实际输入。
这些字符数和 token 估算均不是 provider 的精确输入计费量。

## standard 路径的职责交叉

| 入口 | 当前行为 | 改造时必须覆盖 |
|---|---|---|
| `src/prompts/registry.ts` 的 `PromptSection` / `assemblePrompt` | 按 `dynamic` 分成缓存前缀和动态后缀，另用 `purpose` 标明用途 | 缓存稳定性不能决定指令是否可删 |
| `src/prompts/default-sections.ts` | 行为指导、权限说明、工具说明、技能、项目规则共同组成固定前缀 | 保留各部分来源和用途 |
| `src/config.ts` 的 `buildSystemPrompt` / `buildCustomSystemPrompt` | 默认与自定义提示词使用不同支持段落 | 保持自定义覆盖的既有语义 |
| `src/headless/runHeadless.ts` / `src/hooks/useAgentRunner.ts` | 补充 prepend/append、记忆说明和每轮附件 | CLI/TUI 使用同一 profile，附件不能丢失 |
| `zapsdk/agent/loop.ts` 的 `effectiveSystemPrompt` / `protocolPrompt` | SDK 再折入工具清单、预算和规划/诊断流程要求 | App 精简后不能被 SDK 无条件加回原流程 |
| `src/agent/promptDiagnostics.ts` | 记录真实装配结果的长度、哈希和工具 schema 摘要 | 实验核验使用运行记录，不能只看配置 |

standard 协议要求非平凡任务先建立 3–5 项计划；App 另有计划纪律、文件阅读顺序、
工具选择和子代理使用指导。这些是模型行为要求。权限审批、sandbox 和运行预算
由运行时代码执行，不应通过修改行为指导来放宽。

## 已登记的探索实验

实验 wrapper 只用于评估：替换 `effectiveSystemPrompt()` 的完整固定前缀，保留动态后缀。
短提示词只要求完成用户任务、使用工具、验证结果、诚实报告限制、遵守权限并保留无关工作。
生产代码、模型、工具处理器、权限和预算不变。所有五题按同一实验二进制各运行一次。

首题实际容器已核验：二进制 SHA-256 与登记值一致，模型为 `deepseek-flash`，固定前缀
为 229 字符；工具 schema 哈希和动态后缀哈希与生产基线相同。首题随后因模型流
连续 180 秒无数据触发 `StreamIdleTimeoutError`，execution 为 failed，Harbor 未运行
verifier；这不是官方任务 0 分，也不能用于推断提示词的语义收益。第二题官方得分为 0，
但运行被 `max_repeat` 提前结束：最后五个命令不同，前 120 字符相同，错误地发生签名碰撞。
这同样不能单独证明精简提示词损害解题能力。

探索实验现已完成，五题校验值均与生产基线一致，所有结果和失败轨迹均保留：

| 题目 | 生产基线 `9c561fe4` | 精简提示词实验 | 实验终态 |
|---|---|---|---|
| gpt2-codegolf | 0 | 未评分 | 流超时，verifier 未运行 |
| llm-inference-batching-scheduler | 1 | 0 | 重复签名碰撞导致提前停止 |
| break-filter-js-from-html | 1 | 1 | 自然结束 |
| write-compressor | 1 | 1 | 自然结束 |
| reshard-c4-data | 1 | 1 | 自然结束 |

实验共 3 题通过、1 题官方失败、1 题执行异常未评分；实际运行了 4 个 verifier。
生产基线为 4/5，且没有执行异常。实验结果已收齐，但两处运行故障使解题能力的因果
比较受到干扰，不能把未评分项写成官方 0 分，也不能把不同 cohort 的成功题拼成 5/5。
当前决定是保留生产默认提示词，先验证已修复的通用运行缺陷，再决定下一次提示词对照。
该历史实验没有直接推广。下述 profile 已按独立的 App/SDK 接口实现，仍须完成冻结二进制的完整样本对照。

该处理同时移除了多个指令类别，包括稳定协议、工具补充指导及可能存在的项目/用户
支持段落。因此它检验的是整组指令替换，不是纯粹的长度变化。权限代码仍在，
不代表安全指导或项目指令仍在。即使五题通过，也不能把这个 wrapper 直接交付为生产实现。

实验前已纠正一次错误：初稿连动态后缀也移除了。修正发生在任何实验 trial 开始之前，
旧稿和修正记录均保留。实验启动后不调整处理、题目、模型或预算。

## 生产接口与职责契约

### 一、用途与缓存属性分开

保留 `dynamic` 的缓存语义，为受 App 管理的段落增加明确用途。不要用“固定前缀”作为
删除单位，也不要通过重写 `LoopAgent.prototype` 选择生产行为。

| 用途 | 精简 profile 的处理 |
|---|---|
| 用户指定的 custom/prepend/append、当前装配路径已包含的项目规则 | 保持文本与既有优先关系，不按长度裁剪；自定义覆盖继续遵守原 API 语义 |
| 权限、工具输出信任边界和协议约定 | 保留必要语义；运行时执行约束不变 |
| 工具 schema、参数、结果/后台任务语义 | schema 不变；补充说明只可去重，不得删掉 schema 未表达的必要约定 |
| 环境事实、可用工具、剩余预算、运行结果 | 来源于当前 runtime，保留实际值和生命周期，不能由 profile 编造 |
| 通用行为指导 | 可以精简和对照；不要要求每类任务经过相同数量的计划、检查或反思步骤 |
| 技能与记忆发现 | 保留可用能力、位置及调用参数；分别评估精简方式，不与行为指导合并删除 |

段落分类不提升内容的权限级别。读取到的仓库、网页和命令输出仍按既有信任边界处理。
必须显式传递行为 profile；没有选择 profile 的 SDK 调用保持兼容默认值。

### 二、只有一处 profile 选择

接口为共享的 `PromptProfile = "standard" | "concise"`，由 App 配置或 SDK options
明确选择。`standard` 初期保持默认。profile 沿 runtime factory 传入 LoopAgent，
同时控制 App 的通用行为段落与 SDK 的行为指导；不能只修改其中一层。
App 的配置字段为 `promptProfile`；SDK 使用 `LoopAgentOptions.promptProfile`。没有新增 CLI flag。
Bench 通过显式 adapter kwarg `prompt_profile=standard` 或 `prompt_profile=concise` 选择；未指定时仍使用默认值，
不会从个人配置隐式继承 profile。适配器仅向临时配置增加所选字段，不复制私人提示词或额外凭据。

精简后的固定指导只表达任务目标、验证/诚实报告、保护无关工作和必要工具语义。
规划深度、诊断顺序、是否委派和收尾时机由模型结合用户要求与运行观察决定。
已有硬预算、权限拒绝、取消、资源回收与外部验收语义继续由 runtime 负责。

同一 session 的恢复必须知道先前使用的 profile。profile 未变化时不能重复注入旧协议；
显式变更时重建对应系统消息并让缓存自然失效，不把新旧行为要求叠加。
子代理使用可追溯的 profile 继承规则，不能悄悄回到另一个默认值。

### 当前实现边界

`PromptSection.purpose` 与 `dynamic` 分开。`concise` 替换 App 所有权范围内的通用行为段落，
保留身份、权限和信任边界、工具补充说明、技能目录、项目规则及动态环境。
未分类的扩展段落默认保留；自定义提示词路径继续保留原文本和既有支持段落，不补入整个默认栈。
SDK 同时切换通用协议指导；显式 `required` 规划策略仍生效，profile 不改变执行策略。
子代理从宿主继承 profile，模型的工具参数不能覆盖这个选择。

`standard` 保持既有提示词文本。显式选择 profile 的 SDK 即使没有提供 systemPrompt，
也把协议放入当前系统消息，以便后续恢复和切换替换该消息。未选择 profile 的旧 SDK 调用保留原装配行为。
App 每轮依据当前配置重建系统前缀；恢复后的历史用量诊断保留此前的 profile，新轮诊断记录当前选择。
profile 变化时保留用户历史、工具调用配对和当前动态附件，不把新协议追加成额外用户轮次。
旧 SDK 曾写入历史的无来源标签用户消息不按文本猜测删除。

最初的 profile 实现没有精简工具自身的补充指导、技能和记忆指导，包含其中已有的行为建议。
该轮比较的是 App 通用指导及 SDK 协议的组合变化，不能解释成纯长度变化，也不声称已移除全部行为建议。
改变模型、工具 schema、时限或推理强度须另开对照。

### 后续修正：按实际相关性加载技能

技能目录与 SDK `skill` 描述曾要求“1% 相关也必须调用”，并要求在澄清、计划或编码前
调用任何名字看起来适用的技能。这把技能发现变成了强制工作顺序。现在两处共同要求：
用户明确指定时加载；否则按技能用途与当前工作是否实际受益选择，在相关工作开始时加载。
必要的澄清和无关工作不必等待技能发现。加载指令本身不代表执行了工作或完成验证，技能
指令仍受用户范围和更高优先级指令约束。技能内容、参数校验、权限和执行语义保持原样。

这是后续共享提示词修正，同时影响使用该目录或工具的 profile，包括 `standard`；上文
“保持既有文本”仅描述最初的 profile 拆分。新版本必须记录新的前缀及工具 schema hash，
不能与旧版本视作相同处理条件。已有冻结 Bench 不替换输入；该修正的真实模型收益尚未验证，
不能从一次提前加载技能的观察推断它导致了任务失败。

### 后续修正：按委派收益与实际能力选择子代理

App 工具指导和 SDK `agent` 指导此前把“预计超过四次工具调用”作为默认委派理由，
并把主代理工作限定为单步或紧密串行流程。这是行为硬阈值，不能推导出子任务是否适合
委派。现改为结合独立工作或上下文隔离的收益、子代理实际能力和输入可达性、依赖关系、
协调成本及剩余时间选择，工具调用数量本身不构成委派理由。
用户明确要求委派时仍遵循该要求；角色、预算、审批、隔离和产物合并协议不变。

冻结轨迹中出现过主代理把二进制检查委派给没有 shell 的子代理，子代理如实返回能力限制后
由主代理接手。这个事实支持把能力匹配作为选择条件，但不能证明四次调用阈值导致了该次
委派，也不能证明此次指导调整提高成功率或缩短耗时。新旧行为应使用不同输入 hash 登记；
当前冻结的 89 题 cohort 不替换提示词，后续完整候选验证再评估实际收益。没有增加题目名、
参考答案、隐藏测试反馈或针对题目的路由。原先仅锁定“默认多委派”措辞的测试移除；保留
真实 provider 请求中的 profile 装配、角色能力、权限拒绝、预算和取消行为验证。

### 后续修正：未知图片能力保留输入

模型名未匹配本地规则，只能说明图片能力未知，不能据此删除用户附件或工具返回的图片。
应用层现在保留三态：显式 override 优先，其次 catalog 元数据，最后是模型名的正向提示；
未识别名称返回 `undefined`，让 provider 保留图片。显式或 catalog 的 `false` 继续使用
文本说明代替图片。没有增加特定 Bench 模型名、题目路由或解题提示。

真正收到图片 schema 拒绝时，沿用 SDK 每轮最多一次的移除图片重试，并保留原始会话
中的图片以支持后续切换模型。普通策略拒绝不触发该恢复。应用工厂到 HTTP 的回归测试
覆盖用户与工具图片、能力优先级、成功响应、单次恢复、重复拒绝和普通策略拒绝。
测试证明输入传输与恢复边界，不证明真实 provider 支持图片，也不证明 Bench 得分改善。
正在运行的冻结 cohort 不包含此次改动；后续候选必须单独登记和验证。

### 后续修正：搜索回退的遗漏必须可见

JavaScript 搜索回退此前静默跳过超大文件、二进制文件和无法读取的文件；即使唯一目标
从未被搜索，也会返回 `No matches found.`。现在逐项累计这些遗漏，并在模型可见输出中
报告原因、有效文件大小上限和最多三个经过转义、限长的路径示例。结果达到输出上限时
标记搜索不完整；已找到的匹配继续保留。取消或根路径读取失败仍是失败，不提升为成功。

显式 glob 和 ignore 范围继续生效，权限与文件大小上限不放宽。诊断元数据同时保留计数，
但模型无需额外读取遥测即可知道搜索有遗漏。普通完整空结果保持原格式。此修正针对
JavaScript 回退；没有改变 ripgrep 的搜索、忽略规则或限制语义，也不宣称两个后端的
资源上限已统一。回归覆盖流式/多行、单文件/目录、部分匹配、OS 拒读和运行时更低上限。
冻结 Bench 不包含此候选改动，不能据当前题目分数推断收益。

### 后续修正：评审结论必须标明证据范围

委派评审时，父代理需要区分原始要求、实现假设与已验证观察。子代理的通用指导要求
根据可访问的调用方、测试或其他独立证据核对假设；证据不可用时限定结论，不能把同意
简报中的前提称为独立验证。这段指导保留在自定义角色中，同时继承已有 Host 指令。

这是行为指导，不新增强制工具调用、审批条件、文件传输或权限。明确的用户要求继续
作为要求处理，不能因评审指导被重新解释成可忽略的假设。装配回归仅证明指导抵达
默认、自定义和嵌套子代理，不证明模型会发现错误，也不证明冻结 Bench 的失败已修复。

### 后续修正：传递所选本地执行后端的资源观察

App 在选择本地执行后端时采集一次只读资源快照，将逻辑并行度与可见 cgroup v2
祖先的 CPU 配额、内存限制分开报告。保留分数 CPU 配额；读取失败、格式错误、
未观察或层级截断有明确状态，不将未读到的限制当成无限资源。读取文本和层级深度有上限。
标准/精简 profile、默认/自定义提示词均通过动态后缀传递，CLI 与 TUI 使用同一数据。

VM 或自定义远端后端没有容量观察时，不使用宿主机信息替代。SDK 提供显式的本地
采集函数，嵌入者须在实际执行侧调用。快照只覆盖本进程可见的 v2 层级；不覆盖隐藏
祖先、v1 控制器、其他限制、之后的配额变化或实际吞吐量，不推断宿主架构是否造成模拟开销。
资源观察不调整限制、不选择并行度、不注入安装或构建步骤，也不建立新的完成门槛。
真实容器检查与装配回归不能替代完整候选 Bench，提分收益仍待单独验证。

### 三、可观测，但不增加模型负担

在既有 prompt diagnostics 中记录 profile ID、各段用途及长度和哈希、最终固定前缀哈希、
动态后缀哈希及完整工具 schema 哈希。SDK 协议单独记录为 protocol 段；最终前缀和工具 schema 仍按实际 runtime 装配值计算。
诊断 sink 失败不得使提示词装配失败。不得为了诊断额外持久化凭据或完整私有指令文本。
这些诊断不注入给模型；预算观察继续走原有动态上下文。

## 实施顺序与验收

1. 已收齐探索实验五题的终态结果，包含一题未运行 verifier 的执行异常。
   分别保留生产和实验 cohort；不选择各自成功题拼成一组，不把未评分项记成官方 0 分。
   下一轮先建立符合上述独立解题条件的新基线，再比较模型或 profile；历史探索表格
   只用于定位运行缺陷，不能替代来源资格审查。比较期间冻结输入处理及运行条件，
   同一模型/profile 各保留完整原定题集与全部失败记录。
2. 分层和显式 profile 已接入 SDK/App、子代理与诊断。保留已有 custom prompt、
   prepend/append、AGENTS.md 装配语义，默认继续使用 standard。
   接下来冻结同一实现的两个 profile 做完整对照；若结果未改善，不以“提示词长”
   作为继续删指令的依据，保留实验并重新定位问题。
3. 协议与行为验证必须覆盖下列场景，不能用短提示词字符串快照代替：
   - CLI、TUI、SDK、自定义提示词、子代理、恢复 session 的真实装配结果。
   - 用户/项目文本未丢失，动态环境更新，旧协议未重复叠加，工具定义保持一致。
   - 工具调用成功、权限拒绝、运行截止、后台任务等待及取消，结果各自保持原有语义。
   - 验证失败保持失败；自然结束不冒充外部验收通过；工具输出不能覆盖可信指令。
   - profile 的诊断标识与实际 provider 请求一致，不只验证配置对象。
4. 对最终生产实现执行隔离数据目录的全量 Bun tests、typecheck、native/Linux baseline
   build 和当前提交的 CI。当前 Actions 额度阻止 CI 启动，不能用旧提交的绿色状态替代。
5. 使用最终生产二进制重跑完整原定样本；记录代码、二进制、配置、任务校验值、模型标识、
   所有 trial 与官方评分。探索 wrapper 的成绩不能替代此项。
6. 对观察到的重要差异重复对照，并增加未用于优化的任务，区分轨迹波动与可重复改善。
   一次五题全过只能证明该次固定样本结果，不能宣称全量 Terminal-Bench 或稳定成功率。

回滚单位是显式 profile 选择。新 profile 未证明有效前保留兼容默认值；拒绝通过放宽题目、
放宽官方 verifier、隐藏失败、注入参考答案或隐藏测试反馈取得通过。
