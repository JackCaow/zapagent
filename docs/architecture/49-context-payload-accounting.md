# 上下文附加字段的预算计量

## 已确认问题

OpenAI-compatible provider 会原样回传 assistant 的 `raw` 附加字段，其中可能包含较长的
`reasoning_content`。原 `TokenCounter` 与 `AutoCompact.totalChars` 忽略这部分内容。
一个正文为 `ok`、附加文本为 150,000 字符的通用样例，原实现仅计 5 tokens / 2 字符。

`93aa61f1` 的真实运行记录中，最后一次请求的本地估算为 35,543，服务端报告输入为
136,081 tokens（含缓存命中）。遗漏附加字段是已确认的计量缺口，但估算误差还可能涉及
tokenizer、工具 schemas 和协议 framing；不能将差额全部等同于附加字段大小。
该运行没有发生 context-limit 错误，因此不能据此归因其任务语义失败。

## 实现

- assistant 的可序列化 `raw` JSON 纳入 token 启发式估算与原有正文字符计量。
- 字符压缩触发和保留尾部的尺寸选择使用同一计量方法，避免触发后仍保留未计量的大段历史。
- 不解释附加字段语义，不根据 provider/model 名称分支，不修改或删去协议回传数据。
- 原有完整工具调用/结果配对边界保持不变，保留的最新工具轮次仍携带原始附加字段。
- 非 assistant 的本地 metadata 不作为回传字段计量；图片 base64 不当作模型文本。
  原有工具参数、图片 token 估算规则保持不变。
- 不改变模型窗口、压缩阈值、时间/轮数预算、完成规则或权限。已有阈值会按修正后的尺寸判断。
- 非 JSON 附加对象无法可靠估算时保持计量不抛错；真实请求的协议校验仍由 provider 处理。

这些仍是估算值，不是精确 tokenizer 计数或计费结果，服务端 usage 是已发请求的权威证据。
当前摘要只提取普通消息与工具反馈中的任务事实，不把附加协议字段转成新增任务指令。

## 压缩历史的工具证据

原压缩输入只包含 `message.content`，因此正文为空的工具调用会丢失工具名称、参数和调用 ID，
结果也不包含 `toolCallId`。两个并列检查即使分别报告成功与失败，摘要模型仍无法可靠恢复对应关系。
通用双检查样例已复现；这不是对某一道题的失败归因。

压缩输入现在额外保留 assistant 的工具调用 JSON（ID、名称、参数），并给每个工具结果附上其 ID。
调用片段复用现有 6,000 字符的正文预览限制，结果引用复用 2,000 字符的工具预览限制；
JSON 序列化前先按凭据字段名移除完整值，并对字符串使用现有文本脱敏规则，避免转义引号
破坏凭据边界；随后再截取首尾，截断处显式标记。大型参数与大型调用列表仍是有损预览，
不能将摘要视为完整日志。不可序列化的参数显式标记，保留工具身份。
摘要器不执行这些调用；原消息、保留尾部和 provider 附加字段不受修改。

## 失败工具的诊断反馈

失败工具可能同时返回 `error` 和 `output`。旧模型投影只取 `error`，导致测试断言、部分执行结果等
标准输出被丢弃。命令工具另外只保留 stderr 的错误摘要，摘要之外的行也无法通过结果存储取回。
通用失败命令已复现这两层信息丢失；它们不能单独证明某次 Bench 语义失败的根因。

共享结果正文格式现在同时保留失败说明和非重复的输出，LoopAgent 的 native、XML、非流式路径
以及未预格式化的工具轮次序列化使用相同规则。命令失败、超时和超出输出上限时，`output` 保留
已捕获的 stdout 和 stderr，与成功命令的合并方式一致；错误摘要仍用于快速定位。合并结果不承诺
还原两个输出流的精确交错顺序，也不能取回超出原捕获上限的数据。

正文在原有持久化与压缩入口之前组装，因此大诊断仍保存为可读取的文件并提供有界预览。
结构化失败原因保留在有损预览之外；命令退出码、失败状态、权限与检查结果不因保留输出而改变。
诊断文字仍是工具数据，不能覆盖结构化失败原因或成为新的系统指令。

## 模型可见的进程状态

命令工具已记录实际退出码和显式 `check_steps` 的逐步结果，但原模型投影只发送正文与工具成功标记。
例如 `(检查命令; exit 7) | cat` 的 shell 退出码可以为 0；正文中的失败文字不能被自动解释为
整个命令退出失败，也不能因为工具成功就宣称检查通过。

共享投影现在在正文预览之外提供简短的 `[Execution observation]`：只包含已提供且类型合法的
`exitCode`、`timedOut`、`aborted`，以及显式自检的 `passed`、已观察步骤数和至多 32 个步骤退出码。
未记录的退出码保持缺省；畸形状态不转换为成功。摘要不包含原命令、内部 ID、路径或其他审计字段。
普通工具没有这些事实时不增加状态摘要，也不从工具正文推断结果。

LoopAgent、SingleCallAgent 与未预格式化工具轮次使用同一投影；状态位于诊断压缩和持久化预览之外，
正常计入消息长度和上下文预算。该摘要只保证进入模型反馈，不保证后续有损历史摘要会完整保留它。
显式标注进程/自检状态不等于任务验收，也不能证明管道每一阶段成功。保持原命令、shell 语义、
工具成功/失败状态和完成条件，不自动添加 `pipefail`、强制自检或外部 verifier 门槛。

此项提供更完整的运行事实；是否改善模型纠错和 Bench 正确率必须由新版本运行证明。

### 普通命令的非零退出状态

普通前台命令与显式检查均按实际 shell 退出码报告结果，不再因命令文本含有 `grep` 而把退出码 1
改报为工具成功。旧例外会把 `grep pattern file && false` 中后续检查的失败误判为无匹配。
因此 grep 无匹配现在也返回 `success: false`、`exitCode: 1` 和原始输出；不合成“无匹配”正文。
调用方若接受某个退出码，可以在命令内显式处理。工具失败标记描述本次执行，不代表用户任务失败。
这一修正不更改 shell、管道或命令列表的执行方式，也不按诊断文字推断失败或产物是否新生成。

## 模型可见的执行时间窗口

`remainingMs` 包含运行时已预留给无工具最终答复的时间。只显示总剩余时间，会让模型把答复预留
误认为仍可用于请求和工具执行的时间。`ProgressController.timeBudget()` 同时发布
`executionRemainingMs` 与 `finalizationReserveMs`；两者相加等于 `remainingMs`，预留值在剩余
总时间内截断，执行窗口最低为零。已有的绝对截止时间、动态预留计算和阶段切换保持原语义。

LoopAgent 将两个窗口以毫秒写入原有动态预算上下文，不改变可缓存的 system 前缀。最终答复阶段
要求根据已有证据报告完成项和未验证项，不再提示在无工具窗口内执行验证。旧 SDK 调用者构造的
预算对象可以省略新增字段；缺省时不编造预留值。这是时间事实的补充，不增加新的提前停止规则、
自动回滚或任务专用验证。预算耗尽后仍可能留下未完成产物，不能据此宣称任务通过。

测试核对原始截止边界两侧、预留随已观察答复时延变化、超时后归零，以及实际 provider 收到的
动态上下文与无工具最终答复窗口。改善正确率的结论仍需新的冻结版本 Bench 证据。

## 验证

通用测试覆盖大附加字段、嵌套 JSON、Unicode、非 assistant metadata、图片传输、异常非 JSON 对象、
ConversationManager 计量、工具配对、压缩尾部选择及 provider 原样回传。
Bench 使用新二进制独立运行，旧版本结果保留原归属；无验收器提示或题目专用逻辑。

## 历史图片的批量淘汰与缓存前缀（2026-10-18）

图片生命周期与 token 摘要分开处理。`HistoricalImageRetention` 在发送前按 Base64
载荷字节检查高低水位：默认高水位 32 MiB、低水位 16 MiB。它们是客户端媒体预算，
不是对任一 provider 的 HTTP 限额推断，也不改变模型 contextWindow。
SDK 可通过 `ConversationManagerOptions.imageRetention` 调整水位与保留组数，或设为
`false` 关闭主动淘汰；真实 413 的有界恢复仍独立生效。

达到高水位时，按时间顺序批量移除最早工具组的图片，直到降至低水位或只剩保护项：

- 完整保留用户附件、临时 host 输入及最近两组含图片的工具调用；同一并行工具组不可拆分淘汰。
- 保留所有原消息正文、工具调用和结果配对。图片替换成来源路径、Base64 SHA-256 与
  重新读取提示；引用不是原图副本，源文件可能改变或消失，不能声称已归档视觉内容。
- 同路径后续重新读取的图片属于新工具组，不因旧图已淘汰而被屏蔽。策略不猜测图片语义；
  若仍需旧图细节，由模型根据引用重新读取，未增加模型摘要调用。
- 一次批量操作提交到有效 conversation，后续步骤和新 LoopAgent 沿用，不在每次请求中
  按年龄重选保留集。低水位到高水位之间新图片只追加，旧前缀保持稳定。
- 保护项超过低水位时，下次清理至少等待载荷再增长一个高低水位差，避免每步改写前缀。
  若上游仍拒绝请求，原有 413 恢复可优先触发，保留最近一组和用户附件；安全缩减无进展则停止。
- 只淘汰当前出站视图内的图片，未发送的完整历史不变；保留视图起点，防止腾出 token 空间后
  更旧的历史重新进入请求。终端每批显示一次完成信息，事件为 `historical_images_retired`，
  带组数、前后字节和下一触发水位，不产生审批或等待状态。

缓存前缀稳定仅指两次批量淘汰之间的历史图片部分。淘汰本身会改变前缀；摘要、系统提示或
其他上下文变化也会影响命中。命中率以 provider usage 为准，不能仅用本地哈希推断。
状态保存在当前 ConversationManager 生命周期内；清空、替换会话或 rewind 删除历史时重置
水位，避免旧会话受保护附件抬高的阈值抑制新历史的清理。仅更新 cache hint 不重置水位。
未新增磁盘快照协议。
普通 CLI session restore 不恢复历史工具图片，此次并未扩展跨进程图片恢复能力。
