# 流中断恢复

## 证据与边界

固定五题的 `14e92d98` 运行中，两题因 socket 断开而未进入评分。其中一题的失败请求仅有
thinking deltas；另一题已经输出部分正文。前者适合在明确废弃当前响应后重试；正文或工具开始后的中断采用下述 Agent 续跑协议。
这不是题目解法修复，也不证明恢复后能通过评分。

## 请求协议

`LLMCallOptions.allowThinkingRetry` 由支持清理响应状态的消费者显式开启，默认关闭。
LoopAgent 的流式执行器开启此能力。RetryProvider 仅在当前尝试只产生 thinking deltas、
错误符合已有瞬态错误策略、重试次数未耗尽且未取消时恢复。正文（包括空 delta）、任意工具流事件
或 `done` 一旦出现，该尝试不再允许此恢复。已完成的先前轮次和工具结果不重放。

重试前输出 `thinking_reset`，包含被废弃的尝试编号及机器可读原因。消费端再次检查无正文、
工具或完成状态，发出 `content_abandoned`，清空旧思考及其 ID。新尝试使用新的内容 ID；
旧思考不能形成 `content_final`、进入新响应或恢复会话的模型历史。原运行事件日志保留失败轨迹。
旧 SDK 消费者未开启能力时保持原来的失败行为。

TUI 清理旧预览及延迟绘制，避免取消时再保存废弃内容。stream-json 输出废弃事件；
ACP 在旧 thought message 上追加中断标记，新尝试使用新的 message ID。

## 预算与用量

沿用原请求重试次数、退避、取消信号和运行时截止时间；不重置任务预算，也不修改题目时限。
未获得最终 usage 的失败请求不能按零费用处理。`usageIncomplete: true` 在当前运行总量中保持，
成功重试的已报告 token 数仍正常累计，恢复后的 usage 行及终态保留此标记。
该标记表示已知计数是下界，不估算缺失计费。失败或取消发生在重试期间时，终态也保留不完整标记。
现有 token 限额只能约束已报告用量，不能精确计入服务端未报告的消耗。

根运行的 `provider_request.failed` 同样标记用量不完整，覆盖不重试的正文断流、取消、
尚未收到输出的失败尝试和收尾请求失败。失败请求发出 `providerUsageReported: false` 的
零计数 `run_usage`，表示本次用量未知，使会话持久化能记录缺口；此前已报告的运行总量不清零。
后续成功请求保留不完整标记，新的运行重新开始计数，转发的子代理失败不计入根运行用量。
此记账依赖 provider 的请求生命周期通知；自定义 provider 应遵守同一通知契约。
该记账机制不新增重试，不估算服务端账单，也不改变执行预算或官方评分。

## 验收

通用测试覆盖：思考后断流恢复、默认不重试、正文及所有工具事件之后禁止原请求重放、完成后禁止恢复、
消费者拒绝非法 reset、认证错误不重试、次数耗尽、退避取消、旧工具只执行一次、用量不完整标记、
TUI 预览清理、stream-json 与 ACP 的尝试边界。真实 CLI 使用本地 SSE 故障服务验证已有工具轮次
不重放及会话持久化；这只验证传输和执行协议，不能替代冻结二进制的完整 Bench 验证。

失败请求记账另覆盖：正文续跑耗尽、无输出失败后恢复、收尾请求失败或恢复、取消、
下一次运行清零和子代理事件隔离。CLI 故障探针验证工具副作用仅发生一次，失败终态仍保留
此前报告的用量，会话恢复读取到未知用量标记；成功重试后的最后一条已报告用量也保留该标记。

## 正文与工具流中断后的 Agent 续跑

`9e40edc4` 五题样本中，一次运行在正文和工具调用开始后遭遇 180 秒原始流空闲超时，
未用完任务时间即退出，官方验证未执行。这里需要恢复运行状态，而不是放宽 RetryProvider 的重放限制。

StreamingToolExecutor 在来源迭代器失败后等待已经提交的工具结算，保留真实结果及调用顺序。
参数不完整或尚未提交的调用不会触发结束流时的兜底执行，结果明确标记为“未执行”，并终结 UI 的
pending 状态。工具处理器异常也转为失败结果，避免响应仍在流式传输时产生未处理的 Promise 拒绝。
结算沿用本轮原始取消信号、工具时限及运行截止时间；不启动新的任务，也不绕过工具授权。

`InterruptedStreamError` 携带已结算的部分响应和原始错误。LoopAgent 先原子提交调用与结果，
保存已经展示的正文，并添加运行时中断说明。下一次请求基于更新后的历史发起，原始请求不重放。
截断正文从不进入 XML 工具解析/执行路径。普通正文保持可见，中断说明明确它不是完整回答；
未完成的 XML 标记按现有正文清理规则去除，原始 delta 仍留在事件日志中。

只有来源迭代器的瞬态错误且尚未收到 `done` 才允许续跑；消费端协议错误、认证错误和用户取消不续跑。
每次 run 最多续跑两次，成功的中间请求不重置计数。每次续跑消耗正常的模型轮次预算，原始 deadline、
共享预算、步骤和已报告 token 上限继续生效；达到截止时间则保存结果并进入已有收尾流程。
耗尽续跑次数则保留失败终态。没有正文/工具状态的失败继续由已有 RetryProvider 负责，
Agent 不再给耗尽的思考重试套一层重试。`provider_stream_continuation` 观察事件记录次数和已结算调用数。
原始 provider 失败事件仍保留，缺失 usage 明确标记，不将失败请求视为免费。

OpenAI 兼容适配器用可选的 `thinking_delta.rawDelta` 提供实际收到的推理回传字段片段。
执行器在中断前累积这些字段，续跑时可以回传，即使本次尚未收到 `done.raw`。
思考重试废弃响应时同时清空旧 sidecar；不从通用 thinking 文本推测或构造供应商字段。
其他适配器没有声明的字段不会被注入。已收到 `done` 后迭代器再报错时保留已知用量，但不自动续跑。

测试要求包括真实临时文件只追加一次、未完成参数绝不执行、工具/结果配对、正文中的 XML 不执行、
认证错误与取消停止、整个运行的恢复次数上限、共享轮次预算、截止时间在工具结算时触发，以及
OpenAI 兼容适配器首次响应在 `done` 前中断后的 wire 推理字段回传。原生编译 CLI 的本地 SSE 空闲
故障探针也验证了上述单次副作用、未完成写入不执行、两条结果配对、推理字段回传及未知用量标记。
证据位于 `zap-benchmark-results/harness-stream-continuation-20261015/`（仓库外）。Linux 已交叉编译，
仍需冻结二进制的完整 Bench 运行，不能用这些回归测试替代任务正确性验证。
