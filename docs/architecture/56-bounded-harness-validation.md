# 56. 有界 Harness 验证与交付

状态：本轮有界验证完成，采用服务控制层的确定性修复，不宣称一般解题能力改善。
用户已同意用本目标替代“持续迭代直到 Bench 全通过”。基线为
`84afbe3c9fc87ded8c8c978fd0c5258bc3212704`；原始 Bench 的版本与记录继续冻结。

## 目标与完成条件

处理三个有证据的通用问题，交付可复现的缺陷归因、必要的共享修复、真实运行验收及
采用决定。行为改动最多进行两轮候选对照；负结论是有效实验结果，不为凑通过率扩大范围。

每项必须记录：基线行为、复现步骤、预期契约、实际观察、修改或不修改的理由、验证证据、
剩余限制。已有修复通过验收时记为“基线已覆盖”，不再次计为新修复。真实依赖不可用时
记为“阻塞/未验收”，不能用 mock、跳过或能力声明代替通过。

整体交付要求三项均有上述结论、实际修改完成相关回归、候选有明确采用决定；如候选
涉及模型行为，须完成至少一轮有效对照。未产生行为候选时解释为何不消耗模型请求。
未完成的外部平台验收必须在交付中列出，不能声称完整后台服务能力已经实现。

## 三个优先问题

| 优先问题 | 具体风险 | 真实验收与限制 |
|---|---|---|
| P1 临时诊断与 checkpoint | 模型选择宿主未授权或无法备份的临时路径；父子工作区事实与实际跟踪器不一致 | 授权工作区内真实创建、执行、删除诊断；保留用户文件；工作区外写入仍被拒绝且 handler 未执行；CLI/SDK/子工作区事实与实际范围一致 |
| P2 子 Agent 的源码与能力 | 子任务拿不到需要的源码，角色声明与最终工具集合不同，中断时丢失已经完成的观察 | 子工作区读取显式交付的源码；只读角色不获得额外执行权限；自定义角色不能覆盖 Host 指令；取消时只保留本次已完成、带范围和上限的观察 |
| P3 后台服务生命周期 | Agent 结束后服务消失，或 owner 丢失后错误宣称停止、租约仍有保证 | 普通 run 后台任务按约定停止；显式 owner 的服务跨 CLI 退出仍可达，stop/TTL/正常关闭后不可达；owner 强杀后如实返回 unknown、不自动重启或接管 PID；不支持的 Linux 后端在模型前拒绝 |

P1、P2 的部分修复已存在，先验收再决定是否追加修改。P3 的 macOS 正常路径已有实现，
本阶段先复核实际行为与剩余边界，不把新增容器特权、关闭沙箱或跨 VM 回落作为修复。
Windows、VM 及恶意 daemon 的内核级回收保证不纳入本轮新增实现。

## 顺序、冻结与资源上限

1. 先运行上述契约的现有真实进程/文件/CLI 验收，确认当前缺口。
2. 仅对可复现的共享根因修改。新回归应能区分修复前后，不能镜像实现。
3. 冻结候选源码、二进制、输入、工具、资源、模型及独立验收器，再启动对照。
4. 汇总采用/不推广/阻塞结论，运行相关回归与仓库要求的 Bun 回归后交付。

每次测试或对照运行期间不修改其源码或绑定输入。原始 Bench 不载入本轮候选。
环境准备最多 15 分钟、仅使用已缓存且核验身份的中性镜像；本阶段不再自动拉取大型镜像、
扩大磁盘清理、切 provider 或重试未知状态的任务。先核实原进程终态再处理新运行。
先前 30 分钟镜像测量超时保留为基础设施记录，不续跑，不作为已知完整展开大小。

真实进程契约验收每组最多 120 秒。模型对照每轮最多 12 个预登记 trial、每个 trial
最多 300 秒和 24 轮工具交互、输出上限 16384 token；运行串行，最多两轮候选。
第二轮只用于第一轮发现的可归因共享缺陷，不自动追加。达到上限保留所有终态，禁止选取
重试赢家或为了获取通过结果重复同一单元。

## 模型对照与采用

对照输入使用仓库自有、新建的中性任务，不含 Bench 参考答案、隐藏断言或已提交产物。
模型生成的程序仅在受限临时 Docker 环境执行；Host 只执行可信测试和编排代码。
固定模型、provider、权限、资源和题面，同一任务的两臂运行顺序提前登记，所有单元均统计。
工具/网络可用性不能依据题目名称切换。真实 provider 凭据不进入容器或公开产物。

每轮启动前另行绑定具体 trial 表、输入及验收器哈希，不允许读到结果后改样本、阈值或顺序。
观察独立功能通过率、非预期执行阻断、任务总耗时、请求数及 provider 实际报告的 token；
token 缺失记为未知，不能用字符估算代替计量。小样本只支持该任务集的观察，不声称统计优势。

确定性正确性修复可根据真实复现和回归采用。行为指导类改动没有可复现收益就不推广为默认；
有退化则回退或保留为显式实验项。多项修改打包的对照只支持整体结论，未做消融不得归因到
其中某一项。不通过放宽权限、隐藏失败或要求模型执行固定计划/委派/反思流程来提高分数。

本文件只记录通用契约与实验规则；本机 provider、配置、原始轨迹和私有证据另行保存，
不提交凭据或个人数据。

## 首轮契约验收

- P1、P2：当前相关契约已通过文件、CLI 和子工作区验收，本阶段不再追加提示词或权限修改。
  既往中性模型实验只能支持原登记范围的观察，不能充作本轮候选的新增对照。
- P3：复现两项问题。Bun 下取消 Unix RPC 不一定触发 error，客户端等待可能不结束；
  客户端断连后，owner 正常关闭可能先于仍在等待持久 intent 的启动操作完成。
  候选显式结束取消等待，并在关闭时等待本 owner 的启动操作收尾。
- 新回归在原实现上先失败于取消等待；仅修复取消后失败于提前关闭；两项修复后通过，
  同时确认未晚到启动命令、最终记录为 unknown。普通服务的停止、租约和 CLI 退出路径继续验收。
- 当前已缓存的受限 Linux 容器真实预检在模型前拒绝启动 owner，原因为 required OS sandbox
  不可用。该项记为环境不支持；没有拉取镜像、增加特权或关闭沙箱，也没有把它记为服务验收通过。

## 首轮真实模型对照与采用结论

基线为 `84afbe3c`，候选为 `3b8bfbee`。同一已冻结模型和 provider、同一可信夹具与
语义工具、每单元一次、串行运行。正常场景按基线/候选运行，取消场景按候选/基线运行；
没有重跑、改验收口径或拼接赢家。执行前的本地脚本化 provider 预检单独记录，不计入真实模型结果。

| 预登记场景 | 基线服务契约 | 候选服务契约 | 最终模型报告 |
|---|---|---|---|
| 预置服务跨模型客户端退出存活，Host 随后停止 | 通过 | 通过 | 两版都正确报告 running 与 acceptance unverified |
| 取消等待持久 intent 的启动，再关闭 owner | 取消等待未收敛、关闭提前返回 | 取消等待收敛、关闭等待启动收尾 | 两版都保留 unknown，未宣称成功启动或已停止 |

取消场景按预登记条件注入已有故障，不是随机 Bench 抽样。候选在约 2.1 ms 结束取消等待；
基线在 250 ms 观察上限内仍未结束，不能把该上限解释为其实际完成耗时。两版均未晚到启动
命令，最终记录为 unknown。契约场景通过数为基线 1/2、候选 2/2；模型报告正确数均为 2/2。

| 两个场景合计 | 基线 | 候选 |
|---|---:|---:|
| provider 请求 | 6 | 6 |
| provider 报告的 prompt token，含缓存 | 11428 | 11376 |
| 其中缓存输入 token | 3072 | 6144 |
| provider 报告的输出 token | 640 | 594 |
| 模型循环端到端耗时，秒 | 29.36 | 26.03 |

12 次真实请求均返回 HTTP 200 且报告 usage。Host CPU 未绑定，缓存命中不同，且包含网络和
provider 等待；这些时间和 token 是描述性观察，不能归因为修复导致的推理提速或费用下降。
两场景、每臂各一次，不支持统计优势、一般模型能力提升或完整 Bench 通过的结论。

采用决定：P1、P2 保留已验收的基线契约，不增加提示词和权限修改；P3 采用已复现的取消等待
及关闭收尾修复。第一轮未发现需要第二轮修正的新缺陷，不启动第二轮。

运行时代码完整 Bun 回归为 3958 通过、9 跳过、0 失败；类型检查通过。新增可信模型夹具也按
严格项目设置检查，并通过本地预检和上述四单元真实运行。自有 owner/客户端均已退出，端点
均已关闭，临时配置和 owner 签名材料已移除。原始 Bench 记录保留。

这是 SDK Host 预置服务操作的验证，不是默认 CLI/TUI 服务能力启用。Linux 受限容器的
required sandbox、VM/Windows 真实生命周期，以及 owner 崩溃后的强制回收仍未验收；
不能据此宣称架构 55 的完整 M2b/M3 已完成。可信夹具及运行说明位于
`evals/harness/`，本机原始证据与凭据不提交到仓库。

本轮结果绑定交付提交 `bcda3d18` 中的原夹具及上述两个 SDK 版本。后续 PR review
修正了服务派发键和回执阶段取消；仓库夹具随当前协议更新，不替换本轮冻结文件，
