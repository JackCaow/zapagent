# Shell 目录执行语义

## 问题与边界

执行器曾把前导 `cd PATH && REST` 拆成新的 `cwd` 和 `REST`。这会覆盖显式
`cwd`，从错误的基目录解析相对路径，并把 shell 引号与变量展开误当作文件路径处理。
单独的 `cd PATH` 还有未执行就返回成功的快捷分支，因此不存在的目录也被报告为成功。
这些都是工具执行协议缺陷，修复不依赖任何 Bench 题目或验收答案。

## 执行契约

- `cwd` 指定本次进程的初始目录；相对值按已有 `defaultCwd` 规则解析。
- 前台与后台均把包含 `cd` 的完整命令交给执行 broker，由 shell 处理引号、变量展开、
  目录切换和控制流；不再抽取或模拟 `cd`。
- 单独 `cd` 也实际执行，返回真实退出状态。它的目录变化只属于本次进程，不能改变后续调用。
- `resolveEffects` 仍声明初始目录下的进程执行与文件 effects。这不是对 shell 全部实际读写路径的
  完整枚举，也不证明权限判断已覆盖 shell 内部的目录切换。OS sandbox/broker 的边界继续生效。
- 现有 `check_steps`、取消、超时及 unsandboxed 授权路径保持原有职责；没有新增退出门槛。

## 验证与后续工作

回归测试使用临时目录，覆盖显式相对 `cwd` 与前导相对 `cd` 的组合、`$PWD` 展开、
单引号中的字面量 `~`、不存在目录的失败、独立调用不继承 `cd`，以及真实后台进程的产物位置。
同一候选路径在两种基目录下都存在，以发现静默写错目录的问题。

独立审批矩阵还发现路径写法造成误拦、第二个操作数和分离选项漏判等问题。
本修复不声称解决这些分类器问题；后续需统一审批与执行的路径事实，并明确未知 shell 效果的边界，
不能只放宽某条正则。目录回归通过也不代表 Bench 正确率提高，须保留冻结二进制的完整运行证据。
