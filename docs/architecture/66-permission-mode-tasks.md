# Zap 交互权限模式实施与验收

基线 [v1.14.39](https://github.com/JackCaow/zapagent/releases/tag/v1.14.39) · [调研](64-permission-mode-research.md) · [PRD](65-permission-mode-prd.md)

## 任务顺序

| ID | 优先级与依赖 | 交付与完成条件 |
| --- | --- | --- |
| P1 · 裁决 | P0，R1–R2 | 复用 permission-policy、permissions 和 WorkspaceAccess，固定三档、显式 Ask/Deny、未知范围及撤销的裁决顺序。旧规则无扩权，取消及拒绝不重复弹窗。 |
| P2 · Zap 执行 | P0，P1 | 复用现有执行边界落实项目内与外发权限，去掉可替换的整类 Shell 审批。CP1、CP2、CP4 通过，既有 headless 兼容。 |
| P3 · Codex | P0，可与 P1 并行 | 用真实及 fixture 证据定位 Manual。核对原生设置、ACP 请求、弹窗、回传、取消、结果，完成 CP3。无法执行时给出可操作结果。 |
| P4 · Claude | P0，P1 | 复用 stdio，配置及裁决匹配三档语义。以实际请求与计数通过 CP2–CP4。 |
| P5 · 预览 | P0，P1、P2 | 通用产物预览完成「打开我看看」。复用宿主路径验证与交付能力，核对启动、软链接和远程资源边界。通过 CP1。 |
| P6 · 撤销 | P0，P1–P4 | 根、子 agent、另一窗口、原生在途审批、后台和恢复的旧授权都能撤销。通过 CP5。 |
| P7 · 模式与兼容 | P0，P1、P3、P4 | 更新现有模式、状态栏和用户提示。验证存量 Bypass 降级说明、原有三 Tab、恢复和旧规则。通过 CP4–CP6。 |
| P8 · 验收与复审 | P0，P2–P7 | 精确候选跑 CI 与三条 tmux 录屏，记录版本、通道、授权、审批次数和真实结果。候选 SHA 复审通过。 |
| P9 · 发布与安装检查 | P0，P8 | 单 PR 合并候选。验证 GitHub tag 与合并 SHA、二进制与包校验，核对 npm 版本和 tarball。用已安装版本重放关键剧本并交付。 |

## 三条链路的共同验收剧本

分别使用 Zap、Codex 和 Claude Code 的受支持配置、隔离工作区、独立 ZAPCODE_DATA_DIR、专用 tmux 和本机接收端。记录版本、实际生效模式、审批次数、文件和网络变化。

| 用例 | 通过条件 |
| --- | --- |
| CP1 · 默认用户流程 | 从空目录出网页、修改、构建并打开预览。Auto 的项目内操作 0 次审批，实际文件与已显示画面符合请求。代替同名命令的构建脚本或 Shell 循环仍按实际边界裁决。 |
| CP2 · Auto 对外写入 | 本地模拟未授予目标。结构化外发和间接 Shell 都测批准和拒绝。批准前与拒绝后均写入 0 次，批准后写入 1 次。 |
| CP3 · Manual 往返 | 读直接执行，编辑和发布显示实际审批。Codex、Claude 的真实往返分别通过。拒绝 0、批准 1，断线及取消退出等待且写入 0。 |
| CP4 · Bypass | 开启一次。已获授权的预览、复合 Shell 和对外写入 0 次再次审批。未获范围、命中显式 Ask/Deny 或硬限制时写入 0。旧模式设置不扩权。 |
| CP5 · 撤销和恢复 | 同项目双窗口。设置待审批、子任务和后台续跑，撤销后验证三者均无法继续。重授授权、目录替换与恢复后仍不能续用旧授权，接收端计数不增加。 |
| CP6 · 去噪 | 普通问候直接收尾。失败错误仍显示，拒绝和失败无自动重试，/compact 和恢复后近期拦截可见。状态栏匹配实际模式与等待原因。 |
| CP7 · 兼容和发布 | typecheck、目标测试、全量 bun test、构建及 PR CI 通过。发布后核对 tag、原生产物、registry 版本及 tarball，并用本机安装入口复测关键场景。 |

交付时提供 PR、复审 SHA、GitHub Release、npm、三条录屏和接收端或文件证据。使用者负责线上场景的最终验收。
